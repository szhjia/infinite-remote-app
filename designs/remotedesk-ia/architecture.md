# 遥控台 · 信息架构提案

建议保留一个日常入口，把两种配置拆开：**工作台 → Agent 方案 / 遥控器**。侧栏是导航；只有明确点击「启用此方案」，才会改变实体遥控器正在控制的 Agent。

| 一级入口 | 用户来做什么 | 二级内容 |
| --- | --- | --- |
| 工作台 | 查看现在控制谁、哪些键可用、是否暂停 | 当前方案、快捷切换、动作可用性、下一步 |
| Agent 方案 | 决定某个键在某个 Agent 中做什么 | 方案列表 → 目标应用／键位动作 → 配置／试运行 |
| 遥控器 | 让 Mac 识别实体按键，或定位信号问题 | 连接与输入监控、实体键录入、按键诊断 |

全局标题栏和菜单栏共享「允许遥控触发」及当前方案状态。设备连接、输入监控、辅助功能、总开关分别显示；已连接不代表可以执行动作。保留既有 13 键 RemotePanel（通用布局同样保留），只在它的外面组织导航和上下文。HTML 原型用文字键位表模拟选键，SwiftUI 接入时复用原组件。

## 两条主路径

- 首次使用：工作台显示第一项阻塞 → 在系统蓝牙配对并选择设备 → 开启输入监控 → 录入所需按键 → 返回所选方案试运行。需要发送快捷键时再引导到辅助功能。无需先录满 13 键。
- 日常使用：工作台查看当前方案与可触发动作 → 明确切换。进入方案列表浏览其他方案时，实际使用的方案保持不变。缺少实体信号时，跳到同一键位的录入入口，并能回到原方案及原键位。

## 状态与验收

| 条件 | 界面提示与行为 |
| --- | --- |
| 未选设备／离线 | 明确区分两种情况；提供选择设备或检查蓝牙的入口 |
| 已连接、输入监控未开启 | 显示「已连接 · 未监听」；允许浏览和配置方案，不能录键 |
| 缺实体映射 | 动作可预先配置、单独试运行；该实体键不能触发 |
| 缺辅助功能 | 只阻止需要发送按键的动作；打开网页或应用、切换方案不需要此权限 |
| 暂停 | 不触发实体动作、不可录键，仍可诊断。试运行保持为显式操作 |
| 诊断／录入／编辑 | 保留当前产品的动作隔离；录入与试运行互斥。相同信号重新录入时提示原键位失去该信号 |
| 切换方案 | 不改变实体信号；切换设备不改写方案动作 |

证据：当前 macOS 实况显示 ChatGPT 方案和实体信号同时出现在「方向左」面板；切换设备与切换 Agent 共处同一侧栏。持久化归属核对见 Sources/RemoteCore/Configuration.swift；权限与输入分支见 Sources/RemoteDesk/RemoteModel.swift。
